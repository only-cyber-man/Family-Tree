Mobile hand-off

For the Expo / React Native build in mobile/. Tokens come from tokens.json; screens are in Mobile. Everything below is written so the engineer does not have to guess.

Product rationale

The web builds the tree. The phone answers questions about it.

Building a 100-person graph is desk work: two hands, a big screen, many small drags. The phone comes out in four other moments, and the app is organised around exactly those.

  1. Place a face. Home opens on search. A result shows the person and, if you have set "This is me", the relationship in words ("your mother's cousin") with the step-by-step path behind it.
  2. Know whose day it is. The web's .ics export becomes a live Upcoming list plus opt-in local reminders. No server involvement: everything is scheduled on-device from birth and death dates already in the tree.
  3. Add them now. The centre tab opens Add person with the camera one tap away, then offers to link the new person to someone already in the tree so it never ends up floating.
  4. Browse. A pinch-zoom canvas with level-of-detail rendering and a focus mode that shows one person's parents, partners and children, because the whole graph is unreadable at 6 inches.
Deliberately left out
  • Free-form node dragging. Positions come from birth year and column order; mobile never edits layout.
  • Bulk editing, relationship type management (ft_relationships_names is read-only on mobile).
  • Tree deletion and rename. Owner-only, rare, destructive: web.
  • Account deletion, password change. Links out to the website.
  • Remote push. All reminders are local notifications; there is no notification backend to run.
  • Onboarding beyond two screens. Value, then the one permission that matters.
Needs from the brief that don't fit the data
  • "How are we related" needs a me node per user. Proposal: ft_trees.meNode (or a ft_user_prefs row). Fallback shipped in the design: pick once, store in expo-secure-store.
  • Search by nickname/maiden name needs ft_nodes.nickname. Marked as proposal on the Search screen.

Tab bar. 56pt + bottom safe-area, surface background, 1px top border. Icons 26pt Lucide, label 11pt/600 (700 active). Active colour primary, inactive ink3. The Add tab is a 48pt raised primary circle (shadow md) that opens add-person as a sheet and never becomes "selected". iOS: no large-title nav bars inside tabs; screen titles are Literata 30 in content so they scroll. Android: same bar, Material ripple, no M3 pill indicator except the ripple; edge-to-edge with the bar padded for the gesture inset.
Back. Swipe-back on iOS for pushed screens (path view, invited, tree picker). Android predictive back closes the top-most sheet first, then pops. Sheets are always dismissible by swipe down and by tapping the scrim.
Read-only viewers. Same screens. Every edit control is removed (not disabled): Add tab becomes a "Find" tab (search icon), person sheet loses Edit / Add relationship / Remove and shows the "Shared with you by…" lock row, Settings hides "Who can see this tree". Interaction notes

Sheets, gestures, motion, haptics

Bottom sheets (@gorhom/bottom-sheet)
  • Person: snap points ['38%','92%'], opens at index 0. Handle 36×5, radius 24 top corners, surface bg, shadow lg. Backdrop appears only at index 1 (opacity 0 → 0.45, 220 ms).
  • Filters: ['55%','92%']. Add person / Add relationship: ['92%'] with keyboardBehavior="extend".
  • Tree picker: ['50%']. Confirmations: enableDynamicSizing.
  • Sheet open: 320 ms, easing cubic-bezier(0.2,0.8,0.2,1). Close: 220 ms. Dismiss threshold: 25% of height or velocity > 800 pt/s.
  • Tapping a node while the person sheet is at 38% swaps content in place (crossfade 150 ms), no re-open.
Canvas gestures (gesture-handler + reanimated)
  • Pan: 1 finger, no activation distance; decays with withDecay, deceleration 0.995, clamped to content bounds + 120 pt.
  • Pinch: 0.25 – 3.0 scale, focal-point anchored. Rubber-band 10% past the limits, spring back (damping 20, stiffness 200).
  • Tap node: 44 pt hit slop around dots, selects + opens person sheet. Light haptic (impactAsync(Light)).
  • Double-tap empty canvas: zoom to 1.0 at that point (280 ms). Double-tap node: focus mode.
  • Long-press node (400 ms, owner): quick menu (Edit, Add relationship, Remove). Medium haptic.
  • "Reset view": animate to fit-all in 320 ms; button appears when scale ≠ fit or offset > 40 pt.
Level of detail (react-native-svg)
  • Dot, scale < 0.45: circle r 11 pt (13 selected) filled with the gender border colour, initials 8 pt/700 parchment. Edges 1.5 pt, no labels, no arrowheads.
  • Compact, 0.45 – 0.9: 120×56 card, radius 10, fill + 2 pt border, name 12/700, years 11. Edges full spec, no labels.
  • Full, ≥ 0.9: 150×70 card, 32–40 pt photo/initials, name 13/700, years 11, labels on edges near the selected node only.
  • LOD switch is a 150 ms opacity crossfade, computed once per gesture end (not per frame). Cull anything outside viewport + 200 pt. Above 150 visible nodes, force Dot level regardless of scale.
  • Generation bands: every 20 birth-years, alternating band/transparent, label 11/700 ink3, pinned to the left edge as the canvas pans.
Focus-on-person transition
  • Trigger: "Focus" in the sheet, or double-tap a node. Sheet collapses to 38% first (220 ms).
  • Compute a local layout: person centred, parents in a row above (Δy −190), partners beside (Δx +170, marriage line 4 pt), children in a row below (Δy +220). Everyone else fades to 0 over 200 ms and stops receiving touches.
  • Nodes travel from graph positions to local positions with withTiming(420, easing), staggered 30 ms by ring (self → partners → parents → children). Edges re-draw each frame from animated positions.
  • Camera animates to scale 1.0 centred on the person in the same 420 ms. Success haptic (notificationAsync(Success)) at the end.
  • Header pill "Focused on Anna · parents, partner, children" slides down 200 ms. "Go up to Jan" re-runs the transition with Jan as centre. Exit reverses everything in 320 ms.
Reminders (expo-notifications, local)
  • Ask for permission only from Onboarding 2 or the first "Remind me" tap, never at launch.
  • Schedule on tree load, re-schedule after any node change. Birthdays: yearly trigger, 09:00 the day before, title "{name} turns {age} tomorrow". Remembrance: yearly, 09:00 on the day, "† {name}, {n} years". Round ages (multiples of 5 from 50, plus 18) add a second reminder 7 days before.
  • Cap at 60 scheduled notifications (iOS limit is 64); prefer nearest dates.
  • Tapping a notification deep-links to familytree://tree/<id>/person/<id>.
Durations, haptics, misc
  • Motion tokens: fast 150, base 220, slow 320, focus 420 ms. One easing everywhere: cubic-bezier(0.2,0.8,0.2,1); springs only for rubber-band.
  • Haptics: Light on select, Medium on long-press menu, Success on save / focus complete, Error on failed save (Android falls back to performAndroidHapticsAsync).
  • Toasts: bottom, above tab bar, 4 s (6 s with an action), max one visible, swipe to dismiss.
  • Skeletons after 300 ms; offline banner from NetInfo; writes queue in zustand + AsyncStorage and retry on reconnect.
  • Dynamic Type: all text uses allowFontScaling up to 1.35×; canvas cards and tab labels are exempt.
