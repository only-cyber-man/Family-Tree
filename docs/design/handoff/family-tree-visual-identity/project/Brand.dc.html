Brand foundations

One design system for the Next.js site and the Expo app. Every value here is in tokens.json as a plain hex / px / weight so it can feed CSS variables and React Native StyleSheet from the same file. Other pages: overview · landing · tree view · mobile.

01

Logo system

The mark is a family drawn as a graph: two nodes above, joined through a trunk to one node below. Read top-down it is parents and child; read bottom-up it is a young tree branching. The lower node is copper, the "you" the tree starts from. No leaves, no oak silhouette, no hand-holding figures.

04

Relationship groups

Four groups, each with a color, a dash pattern, a stroke weight and a legend glyph, so they stay distinct in grayscale and for deuteranopia (forest vs copper resolve by luminance and dash; plum sits far from both). Directional relationships end in an arrowhead (vis-network arrows.to, scale 0.7); bidirectional ones have no arrowhead. Same values on mobile via react-native-svg strokeDasharray.

Emphasis within a group
The group sets the color. A second tier sets the weight of the bond. A marriage is the heaviest stroke in the whole graph, a solid 4px beam. "Lives with" is the lightest, 1.25px fine dots. Everything else uses the group default. Until ft_relationships_names.emphasis exists (proposal: strong | normal | weak), map by name in code.

05

Person node

Gender is two muted hues of equal weight: slate teal and clay rose, as a tinted fill with a 2px border. Neither is saturated, neither is "the default". Selection is a 3px copper border, never a fill change. Deceased people keep their hue and get a † before the death year and a 60% desaturated photo. vis-network: shape:"box", shapeProperties.borderRadius:10, borderWidth:2, margin 10/14. The age-scaled border width from the current code is dropped.

Proposals (not in the current data model)

  • ft_nodes.nickname / maidenName (text, optional). Shown in italics under the name in the person sheet and as a search alias. Without it, "Grandma Basia" is not findable.
  • ft_nodes.notes (text, optional). A single free-text field, owner-editable, shown in the person sheet. Not a biography editor.
  • ft_trees.meNode per user (relation to ft_nodes, one per user per tree). Required for "How are we related" on mobile. Fallback in the designs: the user picks "This is me" once and it is stored on-device.
