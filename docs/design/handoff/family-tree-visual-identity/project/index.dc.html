Visual identity, website and native app for Family Tree

One design system feeding the Next.js site and the Expo app, built on the existing PocketBase model (ft_users, ft_trees, ft_nodes, ft_relationships, ft_relationships_names) as read from the repo. Nothing here needs a field that doesn't exist; the three things that would, are labelled as proposals.

Decisions worth knowing

  • Gender: slate teal vs clay rose, equal weight, tinted fill + 2px border. Neither is "default". Selection is a copper border, never a fill change.
  • Relationship groups get colour + dash + weight + glyph. On top of that, an emphasis tier: married is the heaviest line in the graph (solid 4px), lives with the lightest (1.25px dots). Everything else uses the group default.
  • Copper is the marketing CTA and, inside the product, the selection colour. The in-app primary button is forest, so copper always means "this is chosen".
  • Mobile navigation is five tabs (Home, Tree, Add, Dates, Settings). Home opens on search and the upcoming list, not on a list of trees; switching trees is a picker from the title.
  • Age-scaled node borders from the current code are dropped; birth year already encodes age through the vertical position.

Where the brief and the data disagree

  • "How are we related to me" has no me. Proposal: ft_trees.meNode per user; the design falls back to a one-time on-device choice.
  • Dashboard "number of people" is a count query over ft_nodes, not a stored field. "Last updated" uses ft_trees.updated, which changes only when the tree record itself changes; bumping it on node edits needs a PocketBase hook.
  • Invite by email resolves through ft_gettable_users_email, so invitees must already have an account. The UI says so instead of pretending to send invitations.
  • Nickname / maiden name and a notes field are shown as clearly labelled proposals only.
  • The SVG wordmark files embed a Google Fonts import and fall back to Georgia inside <img>; outline "Family Tree" to paths before shipping logo-*.svg.
